## 🎯 Empacotamento Android com Capacitor e Configuração de Build (#92)

### 📋 Resumo da Intervenção
Implementação do suporte completo para compilação e execução nativa do CVMC no sistema operacional Android utilizando o ecossistema Capacitor 8. A intervenção configurou o projeto nativo Android em `frontend/android`, preparou os plugins de ciclo de vida e UX mobile (`@capacitor/app`, `@capacitor/status-bar`, `@capacitor/splash-screen`, `@capacitor/preferences`), ajustou o cliente HTTP (`apiClient`) para detecção dinâmica de plataforma e transmissão de tokens via Bearer token, e adicionou retorno dos tokens no payload JSON das rotas de autenticação do backend Go.

### 🛠️ Modificações por Camada
- **Backend Go (`backend/`)**:
  - `auth_handler.go`: Atualizadas as respostas de `Register`, `Login`, `GoogleAuth` e `Refresh` para retornar `accessToken` e `refreshToken` também no corpo JSON da resposta, além de emitir cookies `HttpOnly` para o ambiente web.
  - `auth_handler.go`: Suporte no endpoint `/api/v1/auth/refresh` para extrair o refresh token a partir do cabeçalho `Authorization: Bearer <token>` quando executando em WebView mobile sem cookies de terceiros.
  - `auth_handler_test.go`: Testes unitários para validar a presença dos tokens no JSON e o refresh com cabeçalho Bearer.
  - `backend/docs/`: Atualizada a documentação Swagger via `./scripts/swagger.sh`.
- **Frontend SPA (`frontend/`)**:
  - `package.json`: Adicionadas dependências `@capacitor/core`, `@capacitor/android`, `@capacitor/app`, `@capacitor/status-bar`, `@capacitor/splash-screen`, `@capacitor/preferences` e `@capacitor/cli`.
  - `package.json`: Criados scripts `cap:sync`, `cap:open` e `cap:build`.
  - `capacitor.config.ts`: Configurado `appId: com.cvmc.app`, `appName: CVMC`, `webDir: dist`, esquema HTTPS e plugins visuais.
  - `storage.ts`: Adicionado suporte a `Preferences` assíncrono para armazenamento de credenciais e tokens em ambiente nativo.
  - `auth.store.ts`: Adicionado gerenciamento e persistência de `accessToken` e `refreshToken` com `setSession` e `setTokens`.
  - `client.ts`: BaseURL dinâmico apontando para a API de produção em runtime nativo móvel caso `VITE_API_BASE_URL` não esteja definida; interceptor de requisição para injetar `Authorization: Bearer <accessToken>`; e suporte ao refresh silencioso com o refresh token persistido.
  - `App.tsx`: Criação do componente `MobileAppBridge` controlando tema da barra de status (`#0284C7`), splash screen e hardware back button do Android.
  - `index.html`: Inclusão de `viewport-fit=cover` e restrição de zoom descontrolado.
  - `theme.ts`: Inclusão de safe area insets (`env(safe-area-inset-*)`), prevenção de overscroll pull-to-refresh e desativação de tap highlight.
- **Plataforma Android (`frontend/android/`)**:
  - Projeto nativo inicializado e configurado com `appId com.cvmc.app`.
  - `AndroidManifest.xml`: Configurado `android:usesCleartextTraffic="false"` garantindo comunicação estritamente segura por HTTPS.
  - Configuração do `.gitignore` e `eslint.config.js` para isolamento dos arquivos gerados.

## 📱 Correção de Layout do Botão Google e Login Nativo no Android (#105)

### 📋 Resumo da Intervenção
Resolução de duas falhas críticas identificadas no fluxo de autenticação e vínculo social com o Google no aplicativo móvel Android:
1. **Layout Quebrado e Overflow no Card de Perfil**: O botão de vínculo oficial gerado pela biblioteca web do Google Identity Services (GSI) possuía largura estática rígida (360px), transbordando as bordas do container em telas estreitas de smartphones. A interface foi refatorada com empilhamento vertical responsivo em breakpoints móveis (`xs`), contenção flexível (`maxWidth: "100%"`, `overflow: "hidden"`) e cálculo dinâmico de largura entre 200px e 380px.
2. **Integração Nativa com Android Credential Manager**: O Google bloqueia fluxos OAuth baseados em popups/postMessage dentro de WebViews embutidas de aplicativos móveis (`disallowed_useragent`). O projeto foi equipado com o plugin nativo `@capgo/capacitor-social-login`, permitindo autenticação nativa através do moderno Android Credential Manager (`androidx.credentials`), devolvendo o ID Token com sucesso para a API do backend Go sem dependência de popups web.

### 🛠️ Modificações por Camada
- **Frontend SPA (`frontend/`)**:
  - `package.json`: Adicionada a dependência `@capgo/capacitor-social-login` compatível com Capacitor 8.
  - `GoogleSignInButton.tsx`: Detecção de plataforma com `Capacitor.isNativePlatform()`. No ambiente nativo, renderiza o botão estilizado com suporte a loading e chama `SocialLogin.login({ provider: "google" })`. No ambiente web, utiliza GSI responsivo com largura adaptada e contenção de overflow.
  - `ProfilePage.tsx`: Layout do card "Contas Conectadas" refatorado com `Stack direction={{ xs: "column", sm: "row" }}`, largura responsiva (`width: { xs: "100%", sm: "auto" }`) e captura de erros através da prop `onError`.
  - `LoginPage.tsx` e `RegisterPage.tsx`: Inclusão do callback `onError` no botão social para feedback imediato ao usuário em caso de falha de autenticação.
  - `GoogleSignInButton.test.tsx`: Bateria de testes unitários cobrindo renderização web, acionamento nativo de `SocialLogin`, tratamento de cancelamento de diálogo pelo usuário e captura de erros.
- **Plataforma Nativa Android (`frontend/android/`)**:
  - Sincronização do plugin `@capgo/capacitor-social-login` com o projeto Gradle e validação de compilação do APK de debug via `./gradlew assembleDebug`.
- **Documentação Canônica (OKF)**:
  - `docs/operations/mobile-build.md`: Adicionada seção operacional com instruções de configuração do OAuth Client ID para Android no Google Cloud Console com o pacote `com.cvmc.app` e as impressões digitais SHA-1 (debug e produção).

## 🔒 Correção de Segurança: Validação Estrita de Client ID e Audience no Provedor Google

### 📋 Resumo da Intervenção
Auditoria de segurança identificou que quando a variável `GOOGLE_CLIENT_ID` não estava configurada (`clientID == ""`), a biblioteca `google.golang.org/api/idtoken.Validate` ignorava a validação do claim `aud` (audience), permitindo que tokens de ID emitidos para qualquer projeto Google pudessem ser aceitos para autenticação (ataque Confused Deputy).

A correção implementada em `validator.go`:
1. Rejeita imediatamente a validação (`ErrGoogleAuthNotConfigured`) se `clientID` estiver vazio ou contiver apenas espaços em branco.
2. Valida explicitamente se `payload.Audience == v.clientID`, reforçando defesa em profundidade.
3. Adiciona suíte completa de testes unitários em `validator_test.go` cobrindo cenários de ausência de clientID, tokens vazios e tokens malformados.

### 🛠️ Modificações por Camada
- **Backend Go (`backend/`)**:
  - `internal/infrastructure/auth/google/validator.go`: Definição de `ErrGoogleAuthNotConfigured` e `ErrAudienceMismatch`, abortando validação caso `v.clientID == ""` e garantindo validação estrita de audiência.
  - `internal/infrastructure/auth/google/validator_test.go`: Testes unitários para validar a rejeição de clientID não configurado e tokens inválidos.
- **Documentação Canônica (OKF)**:
  - `docs/architecture/auth-and-security.md`: Atualizada a especificação de autenticação social com Google reforçando a obrigatoriedade de `GOOGLE_CLIENT_ID` e a rejeição contra Confused Deputy.
